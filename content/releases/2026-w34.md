# WCPOS release notes — 2026-W34

This week WCPOS, the WCPOS plugin and WCPOS Pro were all promoted to v1.10.0. The headline is diagnosability: every sync warning and error now carries a copyable code with a plain-language description, troubleshooting steps and a link straight to the matching help page, and the sync log was rebuilt around it. Syncing also became a better guest on your server — it reads the load your store reports and widens its own cadence instead of adding to the pressure — while tax totals, order money and stored precision were brought into line with WooCommerce. The rest is reliability and speed: stalled first loads, wiped unsent sales, silently discarded orders, stale stock status and a long list of list-rendering slowdowns are fixed.

**Upgrade note:** the app and the plugin now speak a single unified sync journal contract, so update both together — an updated app will not sync correctly against an old plugin, or the reverse. The plugin's sync API is also no longer gated by a setting; the sync routes are always registered.

## WCPOS App

### Added

- Every sync warning and error now carries a code you can copy, with a plain-language description of the event, per-code troubleshooting steps and guidance on where to look in the logs.
- A "Learn more" link on the error help dialog opens the documentation page for that exact code.
- The sync log now shows how long each event took and how it ended, with severity pills, whole-row expansion and continuous scrolling.
- Background maintenance now paces itself against the load your store reports, widening its schedule under pressure and never running in the path of anything you are waiting for.
- Deferred maintenance now has a starvation ceiling, so a permanently busy store can no longer postpone housekeeping forever.
- Debug info now reports your server and plugin versions, and connectivity events have their own log category.
- The camera scanner panel can be resized with a drag handle.
- "Check for changes now" on a row now refreshes only that collection instead of everything.
- Both product lists can be sorted by product type, using the same sort vocabulary the server uses.
- Records that no longer exist on the server are now pruned during the initial load pass.

### Changed

- Scanner outages now appear as a toast at the moment of the scan, instead of a banner that sits on screen.
- Product, cart, reports and tax-rate screens re-render far less: observables are reused instead of rebuilt on every render, contexts were split by how often they change, and rows subscribe only to the fields they actually display.
- Cart writes no longer re-render the products panel.
- Virtualized lists measure themselves outside the render commit, removing a hitch when long lists mount.
- Reachability is now checked with a lightweight ping endpoint instead of loading the full REST index.
- Additional product data is fetched only when a setting that affects it actually changes.
- Idle sync checks now return "nothing new" cheaply instead of re-sending data.
- Totals that include items only known locally are marked with a "+" instead of a footer caveat.
- "How syncing works" now opens the documentation site rather than an in-app modal.

### Fixed

- "Try again" on the crash screen no longer wipes unsent sales.
- Sales the server refuses are now parked for review instead of being silently discarded, and parked conflicts are named and resolvable rather than reported as a generic conflict.
- Tax totals now match WooCommerce: compound taxes are applied in priority order, rounding matches to the cent, and stored tax lines keep WooCommerce's precision.
- Orders now carry the till's own store scope when they sync, so multi-store sites price and file them correctly.
- A first sync could stall for 30 seconds after a foreground load was cancelled; the claim is now released immediately.
- Long catalogue walks could livelock partway through; the task lease is now kept alive during slow fetches.
- Store discovery could spin forever on Connect; probes are now bounded and report a real result.
- The online indicator and manual sync now tell the truth when the server is down, instead of showing a spinner or a green dot.
- Loads released mid-fetch are reported as released rather than as errors.
- The storage ledger was being wiped on every open because worker-wrapped refusals were misread as corruption.
- Browser quota padding is no longer presented as app storage usage.
- A leak in the storage index that produced malformed records — the root cause behind the corruption reports — is fixed, and a failure in one record no longer aborts the whole batch.
- Order write conflicts now recover automatically on the first attempt, and write outcomes are shared across open tabs.
- Stock status and other edits no longer briefly revert after saving; all writeable data now waits for the server's acknowledgement.
- Edit dialogs now close after a successful save.
- Column changes now apply immediately to variable products and their variations.
- The products list no longer jumps near the bottom after a trip through Settings.
- Typing in search no longer triggers a storm of cancelled and re-fired requests as the list reaches its end.
- Changing the app language now reaches every part of the interface.
- Variations with malformed attributes are now dropped at load, matching 1.9 behaviour, instead of breaking the list.
- Editing a product or variation that has no cost recorded no longer fails to save.
- Dropdowns now open on touch on iPadOS.
- Missed barcode scans are logged as warnings rather than errors, the status column is wider, and help links go straight to the docs.
- Data-safety wording for the two most common sync errors now describes what actually happens to your data.
- Notifications and storage measurement now work in the desktop app.
- The camera panel's resize handle no longer intercepts taps meant for the panel.

## WCPOS Plugin

### Added

- Access settings now group capabilities by task, so you can see what a role can actually do.
- Store-side integrity checks now report per-collection totals and let the app filter by what is actually servable, so missing records are spotted instead of guessed at.
- Absence is now authoritative: the server explicitly reports records it will not serve, so the app stops re-requesting them.
- A lightweight public ping endpoint gives the app a fast, cheap reachability check.
- Every WCPOS response now reports the store's current load, which the app uses to pace its background work.
- Sync now runs on a single unified journal — one table, one writer, one contract shared with the app.

### Changed

- Variable products load noticeably faster: variation data and price ranges are now fetched in bulk instead of one lookup at a time.
- Order item identifiers already held in memory skip the locking path entirely.
- Integrity-scan totals are cached briefly, so repeated checks no longer re-scan the catalogue.
- The barcode renderer is now tree-shaken instead of shipping a bundled copy, cutting about 1 MB from the plugin.

### Fixed

- Cashier and cash-tender details are now visible inside the order snapshot, so receipts and audits show who took the sale.
- Store reassignment on an order is now authorised and applied before the order is written.
- "Any …" variation selections survive the write path instead of being lost.
- Orders forwarded from a till keep that till's store scope, so store-specific pricing holds.
- Coupons keep their modified date when pushed, so the app stops re-syncing them.
- Gateway amounts — cash change and card cashback — now render in the order's own currency.
- Refusing an order deletion now leaves the order completely untouched.
- Print jobs that fail on retry stay marked "Needs attention" and can no longer be retried twice.
- Restoring a trashed order now records the correct row when high-performance order storage is in use.
- Role capabilities are re-synced whenever the definition changes, not only after a version bump.
- Products with reordered categories or tags no longer produce false sync conflicts.
- SKU and Global Unique ID are always offered as barcode field options.
- The POS web bundle is revalidated on every boot, so a stale bundle can't persist after an update.
- Settled sync rows are now expired by the daily purge instead of accumulating.
- Uninstalling the plugin now removes its data.
- Date formatting no longer leaves a stray space before punctuation when the AM/PM marker is omitted.
- The ping response is completed before shutdown handlers can add anything to it.

### Removed

- The sync API feature gate is gone — sync routes are always registered.
- The non-functional StarPRNT fixed-layout print output was removed.

## WCPOS Pro

### Fixed

- Store reassignment on an order is now properly authorised on the Pro side.
- Store-scoped product pricing is restored, so each till shows its own store's prices.
- Update checks now use the current Pro update endpoint and report the available version consistently.
- The fast ping path now also runs when Pro is active.
- Uninstalling Pro now removes its data.

## Updates Service

### Fixed

- Upgrade notices are served again to sites checking for Pro updates through the older endpoint.
