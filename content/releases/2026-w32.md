# WCPOS release notes — Week 32, 2026

Weekly summary of changes across WCPOS products. PRs merged from July 27 to August 3, 2026.

**Shipped this week:** WCPOS 1.9.14 and WCPOS Pro 1.9.14.

## WCPOS App

### Added

- Every error now carries a short error code. Quote it in a support ticket and we can find the exact cause straight away.
- Logs are kept automatically and cleared on a schedule, so a problem you notice on Friday is still traceable on Monday without logs growing unchecked.
- When an error happens, the app now attaches a recording of what led up to it — no need to reproduce the fault with debug mode switched on.
- Sync activity is recorded in far more detail, including where each sync left off and anything that looks out of place.

### Changed

- Product lists are now sorted, filtered and paged by the local database rather than in the app. Large catalogues browse and scroll noticeably faster.
- When the POS sits idle, it checks in with your store less often and backs off gradually. Less network traffic, less battery drain on tablets.
- Switching between stores now loads the new store fully before it takes over. If the switch fails, you see why instead of landing in a half-loaded store.
- Customers are fetched when you actually need them, with a slow background top-up. Opening the POS no longer waits on a customer download.
- The Logs, Database and Performance screens have been rebuilt around a consistent layout — a single attention panel that tells you what needs looking at, plainer tables, and clearer coverage indicators.

### Fixed

- Draft, pending and private products no longer appear in the POS catalogue.
- Products and variations are listed in your store's own order again.
- Barcode scanning resolves against local data again, so scanning works without waiting on the network.
- The search box keeps focus while you type.
- Clear & Sync no longer crashes partway through.
- Clearing local data no longer hangs indefinitely, and if it does get stuck, the next attempt recovers instead of blocking.
- Resetting one list no longer disturbs the sync position of the others.
- Voiding an order now falls back to setting it to pending when your store refuses order deletion, instead of failing without explanation.
- Order details no longer show raw metadata that was never meant to be displayed.
- Selecting the guest customer no longer triggers a pointless customer lookup.
- Variable products without sale prices no longer report a database error.
- Routine session refreshes are logged as normal activity instead of warnings.
- Fixed the desktop app refusing to open the POS with "An object could not be cloned".
- General reliability work across sync, customers and logging.

## WCPOS Plugin

### Added

- Orders now include their POS receipt link, so the receipt can be reopened from the order itself.
- Anyone with a user account can be set as the customer on a sale again, including staff and admin accounts.

### Changed

- The app now checks for store changes with a single lightweight request that returns nothing at all when there's no news. Fewer requests, less load on your server.
- Product images in the catalogue are served at medium size instead of full size — quicker loads and less bandwidth.
- Only published products count towards catalogue checks, so counts match what you actually sell.

### Fixed

- Receipt timestamps follow your WordPress time format setting, so 12-hour and 24-hour stores each get the right one.
- Fractional quantities work again for items sold by weight or length.
- Deleting an order restores its stock.
- Coupons stay on an order when the order is updated.
- Order line items keep their link to the product they were sold from.
- Discounts applied as a negative fee are now taxed correctly.
- Customer metadata and tax IDs are preserved in both directions, including when a sale is pushed to your store.
- Custom barcode fields stored in product metadata can now be used as barcodes.
- Customer sync no longer stalls when your customer list includes staff or admin accounts.
- Sync integrity checks repair themselves instead of getting stuck when their records are missing.
- An interrupted database upgrade is retried cleanly rather than leaving the store part-upgraded.
- Print jobs can only be cancelled while they are still waiting, and cancelling can no longer affect anything other than genuine print jobs.
- PDF receipts no longer fatal on PHP 8.4.

## WCPOS Pro Plugin

### Added

- Release notes and upgrade notices now appear in the WordPress plugin details, so you can see what's in an update before installing it.

### Fixed

- Receipt PDFs no longer fatal on PHP 8.4.

## Updates Server

### Changed

- Update responses now carry tidied release notes and any upgrade notice, which the plugins display in WordPress.
